# What surprised me and what still concerns me

What surprised me most was how hard it was to come up with a bug to inject in the first place. It is easy to overlook a bug during development, but difficult to inject one on purpose. I broke the package twice by accident without trying. After renaming it, the old name was still in the entry point: build and install passed, importing a module worked, and the command crashed. Later I left `from datetime import UTC` in `main` with lint and tests green on Python 3.13, and it was found only when the wheel was run on 3.10. Designing a bug that keeps a naive pipeline green was much harder, because I first had to work out how a CI runner differs from a user's machine. What still concerns me is that the pipeline only catches what I thought to put in it. Linux ARM was fully green until I added a runner for it, and I do not know what the next missing case is. The build tools are also not pinned by hash, so a compromised build tool could change the wheel while every check passes, and the check of the published package runs only after an upload that cannot be undone.
